# 创造固定分析流程

将生物学问题转化为研究者可理解、计算定义明确、经过小规模验证、可版本化复用的分析流程。流程必须同时交代“算出了什么”和“能够说明什么”。以科学适用性、统计有效性和计算可行为依据，不承诺一定发现预期生物学信号。

## 决策分工

- **适用的通用知识和惯例：自主采用。** 先确认适用条件，没有实质争议、且不违背已有研究定义时直接使用。将选择、依据和实际配置写入详细方法记录，不逐项询问，不在正文堆叠常规设置。
- **可查明的不确定性：先自行消解。** 阅读现有项目资料、检查数据、查证原始方法或官方文档，必要时进行范围受控的小规模试验。不能把尚未调查的问题直接转交研究者。
- **未决科学取舍：交给研究者。** 若合理选项对应不同研究目标、估计对象、样本总体、比较关系或解释范围，且现有指示与证据不能确定，应提交清楚的决策卡。方法存在会实质影响结果的未决不确定性时同样处理。
- 区分“方法很常见”与“在当前问题中适用”。决定是否提交，依据当前语境中的科学影响与证据，不能仅按参数名称分类。
- 优先读取并复用研究者已有决定。未收到答复不能视为同意；研究者已明确授权的事项也不重复索取许可。
- 未决事项只阻止依赖它的工作。继续整理定义、调查证据和执行不依赖该决定的检查。临时假设可用于已授权范围内的有限比较试验，必须明确标注，不能流入冻结版本或正式全量结果。

开始分配决策权或遇到选择分歧时，读取 [决策与沟通](references/decision-policy.md)。

## 工作流程

### 1. 接续上下文并界定问题

先检查已有研究计划、数据字典、流程代码、配置、分析记录及历史决定。保留项目已有语言、文件组织和执行工具，不为本 skill 更换分析平台。证据区分为用户提供的声明、已读取的历史记录、本次直接检查和本次实际运行结果；准确注明来源，不重复验证仍有效的已有证据，也不将摘要升级为本次已核验。

形成一份简洁的研究定义：生物学问题、研究总体与单位、比较或估计目标、输入数据、关键混杂因素、支持与不支持的解释、预期交付物。观察单位、独立重复单位和抽样单位必须分清。描述性、探索性、验证性或预测性用途按实际标注。

自动填入有依据的内容，将真正影响下一步的未决事项集中提交。若缺少数据或无法执行，可以完成设计草案和验证计划，但不得声称已验证或已完成冻结。

### 2. 定义步骤、接口与参数

读取 [分析定义](references/analysis-definition.md)。用依赖图展示数据流，为影响科学含义的步骤建立定义卡；纯文件转换等辅助步骤可合并记录。

每个关键输出明确数值定义、单位或尺度、方向、参考/背景、假设、生物学解释和限制。涉及统计推断时补充比较、误差控制及重复结构。检查相邻步骤的数据层、样本集合、标识符和维度是否相容。

参数区分科学定义、方法选择、数据适配和执行资源。固定适配规则、适用范围、异常处理；同时保存每次运行解析得到的实际值。不能为“普遍适用”任意指定跨平台、跨物种的统一阈值。

### 3. 进行有限的小规模迭代

读取 [验证、冻结与复用](references/validation-and-freeze.md)。先写候选方案、检查指标、预算和停止条件，再运行试验。

区分最小运行测试与代表性生物学试验；按问题保留独立重复、分组、配对、批次与重要异质性。记录抽样方法、随机种子或固定清单，以及缩减数据改变了哪些性质。按需要增加独立验证数据或多数据集检查，不把单个试验的成功称为广泛通用。

同时检查计算正确性、统计可靠性、生物学解释与资源消耗。生物学验收不能等同于获得期望方向、显著性或漂亮图形。不能为了通过验收，事后静默修改标准、挑选样本或背景集合。

每轮记录动机、改动、结果、判断与保留/放弃原因。优先复用未改变的计算，避免无目标的全参数搜索。新增证据无法消解的科学取舍提交研究者，其余在既定范围内继续推进。

### 4. 验收并冻结

只有影响结果含义的定义已确定、约定验证已通过、适用边界已说明、资源计划可行，才可标记“已冻结”。冻结记录必须关联实际代码/脚本、结构化配置、软件与参考资源版本、验证证据及已有研究决定。

冻结状态记录可复用方案；每次运行另外记录输入清单、解析后的配置、随机性设置与输出，不把第一次输入写成唯一允许的输入。

冻结是技术和科学验收，不额外创造一次强制批准流程。已有授权和决定充分时完成冻结；仍有需要研究者决定的科学问题时保持候选状态。仅请求创建流程不等于请求消耗资源运行全量。

### 5. 按范围执行、复用或修订

全量执行必须同时满足：用户任务已涵盖该执行、当前使用的是已验收的冻结版本、新输入通过适用性检查、实际配置符合冻结规则、资源需求在约定范围内。实现流程时让全量入口校验这些条件，并输出具体未满足项；不能仅凭一个 `frozen: true` 字段跳过检查。

必要且成本受控的全量元数据检查或轻量质量概览可以先做，须与完整计算区分并遵守预算。小规模估计不能支持资源可行性时，先完成有界的规模试验。

全量后依据预定标准验收，记录新出现的限制。若需要改变冻结定义，保留旧版本与结果，创建候选修订，验证受影响部分后发布新版本。输入变化无需自动修改方法版本，但必须生成新的运行记录并检查适用性。

## 研究者可见的产物

复用现有项目文件；没有约定时，在项目的 `analysis/<分析名>/` 下维护以下逻辑内容。可合并短文档，不创建没有用途的空模板。

1. **分析说明**：研究问题、流程图、步骤定义、解释边界、当前状态与未决事项。
2. **结构化配置**：参数值、适配规则、允许范围和资源设置；采用现有 TOML/YAML/JSON 格式。
3. **分析证据记录**：默认选择及依据、研究者决定、试验计划与结果、关键诊断图、样本流失及资源测量。
4. **冻结与运行记录**：冻结清单及内容标识，每次运行的输入、实际配置、状态和输出位置。

正文先展示科学目标、当前结论和需要研究者决定的事项；常规选择放在详细方法中，以脚注、附录或可展开区域呈现。低干扰不意味着省略依据或隐藏会影响解释的问题。

结构化配置是执行值的唯一来源，文档引用或生成这些值，避免手工维护两套相互矛盾的参数。每张关键图表与结论可追溯到步骤、输入、配置、代码版本和试验/运行记录。

## 个人科研绘图风格

绘图采用用户维护的 [yxwucq_skills](https://github.com/yxwucq/yxwucq_skills) 中的两套规范，使用本地已安装版本：

- 小规模试验、质量检查、分布与趋势初看：使用 `exploratory-scientific-plot`，读取其 `SKILL.md`，采用 `explore` profile。
- 用户要求用于正式科研总结、报告、PPT 或论文的图：使用 `formal-scientific-figure`，按介质选择 profile，并交付完整 Figure legend。
- 两类图共用项目实际生效的 `plot_style.toml` 和稳定的组别颜色。没有配置时使用个人绘图 skill 的模板创建；已有项目遵循其配置查找和更新规则，不另设竞争的样式文件。
- 视觉细节以对应绘图 skill 为准，不在本分析 skill 中复制配色、字体或尺寸。用户当次明确指定的风格与项目已确认规范优先。
- 如本地缺少对应绘图 skill，先检查已连接的个人技能仓库或项目内的同名副本；无法取得时说明缺失，继续不依赖绘图的分析，不声称已经应用个人风格。

结束时说明实际完成阶段、产物位置、验证结果、未解决限制与下一步。严格区分“方案已写好”“试验已通过”“已冻结”和“全量已验收”。
