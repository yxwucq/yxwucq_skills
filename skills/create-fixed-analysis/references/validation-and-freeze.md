# 验证、冻结与复用

用于计划小规模试验、限制计算成本、验收方案、记录冻结版本和检查新输入。验证深度与任务风险和规模匹配，不要求所有流程采用相同测试或阈值。

## 小规模试验计划

在观察候选方案结果前，记录待验证的问题、候选方法/参数、数据选择、检查指标、通过标准、预算及停止条件。已有可靠项目标准可直接使用；涉及科学取舍且尚未确定的标准按决策规则提交。

| 数据用途 | 设计 | 能够支持的结论 |
|---|---|---|
| 最小运行测试 | 微型真实数据或具有可知结果的构造数据，覆盖关键接口/边界 | 实现、接口和已覆盖的数值计算是否正确 |
| 代表性试验 | 保留与研究问题有关的分组、重复、配对、批次和异质性 | 当前数据范围内的方法适用性、敏感性与解释能力 |
| 独立验证（适用时） | 未参与候选选择的数据、外部数据或预先隔离的验证划分 | 对未参与选择的数据的泛化表现 |
| 规模试验（需要时） | 有界的几个代表性规模，覆盖主要耗时与内存步骤 | 全量资源计划是否可信 |

不要按固定百分比抽样而忽略实验结构。优先减少不破坏问题定义的维度；记录缩减如何影响测序深度、稀有群体、特征空间或检验背景。试验仍无法覆盖关键结构时，应扩大合适的部分或收窄验收结论。

小规模样本不足时，未检出信号不能单独证明方法无效。构造数据的已知信号也不能单独证明真实生物学有效。只有一个数据集时，声明已验证的范围，不将其称为普遍适用。

## 验证证据

按实际用途选择检查，提前说明指标如何计算：

- **计算正确性**：可知结果、手算例子或可信参考实现；数值容差、维度、单位、标识符与样本流转。
- **统计可靠性**：独立重复与模型设计、合理的空模型或阴性对照、误差控制、效应大小及不确定性。置换必须遵守可交换性与配对/分层结构，不能任意打乱标签。
- **生物学解释**：预先指定的正负对照、独立证据、与目标量一致的解释。用于调参的标记、基因集或先验不能同时冒充独立验证证据。
- **稳定性**：关键参数合理邻域、不同抽样或随机种子下的变化；明确比较的是数值、排序、群体结构还是结论。稳定不能替代有效性。
- **资源可行性**：墙钟时间、峰值内存、磁盘/中间文件规模及环境；逐步识别瓶颈和主要规模变量。

预测或需要独立验证的分析，应在正确的独立单位上划分数据，并在训练划分内完成需要拟合的预处理与参数选择，防止信息泄漏。只有条件允许时才使用独立验证；无法实施时明确证据限制，不能将探索结果改名为验证结果。

## 迭代记录与停止

每次试验记录：试验 ID、候选版本、待验证问题、输入清单/抽样、代码与配置标识、改动、预期、实际结果、资源测量、判断和后续动作。保留失败和放弃的方案及简短理由，不只保存最终成功结果。

达到事先约定的正确性、适用性、稳定性和资源要求即可停止；不为微小改善无限搜索。预算耗尽、候选均不适用或关键证据不足时，整理已完成证据和可选下一步，不自行扩大范围或放宽验收。

验收标准若确需修订，记录原因、旧新标准、已看过的结果以及是否需要新的验证数据。不得静默变更标准以获得期望结果。

## 计算效率

- 先测量瓶颈；模型拟合、图构建、置换或两两比较等步骤可能具有不同扩展规律，不从总时长直接线性推算。
- 复用未变化的中间结果，缓存键应覆盖输入内容/版本、代码、配置及相关参考资源，避免误用旧结果。
- 在科学定义允许时使用稀疏表示、分块或并行；验证输出等价性或已约定的近似误差。
- 全量计划包含预计范围与不确定性、主要瓶颈、磁盘需求、失败/重试上限及恢复办法。规模证据不足时先做有界检查。
- 不为速度省略独立重复、错误简化背景或降低验证标准。存在科学效力与成本的实质取舍时提交决策卡。

资源上限未给出数值时，先读取现有预算、执行配置和环境信息。常规分块等实现参数可在已授权范围内自行设置；无法确定的上限保持未解析。只有下一项工作确实依赖缺失的成本/规模决定时才询问，不把资源可行性写成已通过，也不要求研究者逐项选择实现参数。

## 状态与冻结条件

通常使用：**定义中 → 小规模验证中 → 已冻结 → 全量验收完成**。冻结版本可以在不同输入上有多个运行状态；某次运行失败不会抹去其他运行的记录。

阶段之外记录实际进展和等待原因，例如“设计草案完成，待数据，试验未开始”。单次运行单独记录待预检、预检阻断、运行中、失败或验收通过；新运行被阻断不等于旧版本失去冻结状态。

冻结前核对：

1. 关键研究定义、步骤接口和科学取舍已确定，已有决定可追溯；无临时假设冒充正式定义。
2. 已完成约定验证，有实际证据、限制和适用范围；失败项已处理，不能用“已填写”代替“已通过”。
3. 参数值/规则、候选边界、超界行为明确，文档与实际实现相符。
4. 代码/脚本、环境、参考资源可以定位并复现；尚未实现的设计只能标记为设计草案。
5. 资源计划具有足够依据；全量产物、检查条件和失败处理明确。

冻结标准不能要求研究结果显著或一定符合预期。不能声称用户确认了其未确认的事项；已经授权或确定的内容也无需再次确认。

## 冻结清单与运行记录

优先沿用项目版本系统，至少保留下列可定位信息：

| 冻结清单 | 每次运行记录 |
|---|---|
| 流程 ID、版本、冻结日期与实际状态 | 运行 ID、流程冻结版本、开始/结束与状态 |
| 分析规格和关键研究决定 | 输入文件/数据集清单与内容标识、样本元数据版本 |
| 代码提交或实际文件内容哈希 | 实际使用的代码/环境/参考资源标识 |
| 配置与适配规则的内容标识 | 解析后的全部实际参数与随机种子/随机性设置 |
| 软件、环境锁定文件或容器标识 | 硬件与资源测量、警告、失败/重试信息 |
| 参考基因组、注释和数据库版本/内容标识 | 输出清单、关键检查结果及与输入/步骤的关联 |
| 已验证适用范围、证据记录、已知限制 | 与冻结定义的差异检查及运行验收结果 |

未提交的代码需记录实际内容，不能只记 Git 提交号。外部动态资源需固定版本、快照或可核验内容；无法固定的部分明示复现限制。浮动的 `latest` 标签不足以代表冻结环境。

复现要求按方法明确：确定性输出可要求数值一致；存在硬件/并行等影响时使用预先说明的数值容差或科学结果等价条件。保存随机种子不能单独保证完全一致。

## 全量入口与复用检查

在完整计算前核对，而不是只检查状态字符串：

- 当前任务授权涵盖全量执行及其资源范围。
- 配置、代码和参考资源符合冻结清单；允许变化的执行参数在已验证范围内。
- 新输入的模式、数据层、测量平台/物种、标识符和实验结构满足本流程已声明的条件。
- 参数适配的统计量在验证范围内，无未处理的异常或失效前提。
- 预定质量检查和资源检查通过；错误能指出步骤、具体问题及处理方式。

输入变化但仍在范围内：沿用冻结流程，保存新运行记录和适配后的实际值。仅调整已允许的资源参数：记录该次设置并按规定检查等价性。

科学定义、算法、适配规则、关键参考资源或超出已验证范围的变化：创建新候选版本，评估影响并验证相关步骤和下游结果，不覆盖旧冻结记录。升级软件是否需要新版本取决于其是否改变冻结实现与结果保证，必须记录并核查，不能静默漂移。

全量遇到失败或新现象时，先区分实现/资源故障、适用条件失效和新的科学问题。只有在已允许的重试或资源调整范围内自动恢复；需要改变科学定义时回到决策与验证，不为了完成运行临时修改方法。
