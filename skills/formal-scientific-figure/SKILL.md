# 正式科研绘图

把科研结果组织成可用于报告、汇报或论文的图。参考 KOLF2.1J Perturbation Cell Atlas 的视觉语言：数据结构清楚、颜色含义稳定、重要对象就近标注、辅助信息紧凑。正式程度体现在信息与排版质量，不等于增加面板数量。

## 工作方式

1. **确定用途和主信息。** 从用户请求判断是 Markdown、PPT 还是论文。明确读者应从图中理解的一个主要问题；不把描述性关联改写成因果结论。已有探索图或分析结果时，复用其数据处理口径。
2. **先处理配置。** 读取 [项目配置约定](references/project-config.md)。查找和沿用已有绘图 TOML；没有时使用 [默认配置](assets/plot_style.toml) 创建 `plot_style.toml`。正式图与探索图共用组别颜色；用途只切换尺寸、字号、标注和导出 profile。
3. **根据承载介质选 profile。** Markdown 选 `formal_md`，PPT 选 `formal_ppt`；只有明确制作论文图才选 `formal_paper`。没有其他线索时按 `formal_md` 开始并说明。具体规则见 [交付与文字组织](references/formal-delivery.md)。
4. **组织图的阅读顺序。** 按“总体结果 → 关键比较 → 必要验证”安排内容。保留最有解释力的面板；主体、辅助图、图例和图注分工清楚。采用 [视觉规范](references/visual-style.md) 完成配色、坐标、色条和标签设计。
5. **编写完整 Figure legend。** 每张正式图提供能够独立解释整图的连贯图注：先给简短图题，按 a、b 等顺序描述面板，再说明相关的数据处理、颜色、样本量、统计方法和必要限制。副标题、散落的小注释、色块图例不能替代完整图注。图内仅保留读图必需的标题、面板字母、坐标轴、色条/组别图例与重点标签；长方法说明放图外。具体要求见 [交付与文字组织](references/formal-delivery.md)。
6. **让代码包含最终设计。** 颜色和风格参数来自 TOML；关键标签、色条位置和面板布局尽可能可复现。布局特殊值放入相应 figure override，或保存为随图的标注布局数据。完整图注正文存为随图的 `figure_legend.md`，由报告或 PPT 流程使用；不要压成图片底部不可读的小字。
7. **按最终尺寸检查。** 先预览独立图，再检查图与完整图注是否对应；若用户要求制作报告或 PPT，就在对应文档工作流中检查最终页面或幻灯片。修复影响解释或阅读的问题。仅生成图片而未检查最终承载文档时，如实说明检查范围。

## 输出

- 按介质提供可编辑或矢量版本与合适的预览图，默认文件类型见 TOML。密集数据层允许栅格化，文字和坐标轴尽量保留矢量。
- 默认交付完整 Figure legend，正文与图片一起交付。Markdown/HTML 报告紧接图片完整呈现；PPT 同时提供可复制的完整图注，必要时置于配套图注页或备注，不用几条小注释替代，也不缩小到不可读。涉及样本量、误差线、检验和校正时，用实际方法描述；缺失信息标记为待补，不自行编造。
- 将配置变更、输入口径与绘图代码保存在项目内，使后续图能够沿用。已维护的脚本或 notebook 原位更新，避免大量一次性重复文件。
- 本技能负责图；用户另有完整 Markdown/PPT 交付请求时，在当前任务中继续完成该交付，并采用可用的文档/演示工作流。本技能本身不构成创建或发布新网站、文档或幻灯片的额外授权。

## 参考与边界

首次匹配 KOLF 风格或处理陌生图型时，查看 [素材与证据](references/sources.md) 中相关论文图及 notebook 原始输出。素材用于观察风格，不作为新研究的分析数据，不复制原论文的生物学结论与标签。

字体、字号、点大小和颜色是起始建议，不是固定出版标准。当前用户要求和项目明确规范优先；为美观而改变点位、隐瞒截断、添加无依据星号或压低不利结果均不可接受。
