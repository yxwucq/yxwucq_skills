# 项目绘图 TOML 约定

两种技能遵守相同约定。这里的 `plot_style.toml` 是本工作流定义的项目文件，由绘图代码主动读取；Codex 或 Matplotlib 不会自动识别它。它与 Codex 的 `config.toml` 无关。

## 查找与选择

1. 以用户指定项目根目录为准；否则使用当前仓库根目录。没有仓库时使用当前任务工作目录，不把用户主目录当成项目根目录。
2. 先读适用的项目说明与现有绘图入口，查明是否已指定配置文件。用户明确指定的文件优先，其次是现有绘图流程实际使用的配置。
3. 用文件搜索检查任务目录到项目根目录之间的 `plot_style.toml`，以及项目常见位置 `config/plot_style.toml`、`config/plotting.toml`、`figures/plot_style.toml`。若已有不同命名的配置，应通过绘图脚本的读取语句或项目说明确认，不凭文件名猜测。
4. 有多份配置时，不自动合并不兼容的 schema。采用当前工作流明确引用的那份；若没有证据而且选择会改变输出含义，简短询问。子目录配置仅在项目明确使用时覆盖根配置。
5. 已有项目但没有专用 TOML 时，先从当前绘图脚本和已有图中提取可以确认的颜色映射，再创建根目录 `plot_style.toml`。只对缺失的设置应用 KOLF 默认值；不要将已有项目直接重置成默认样式。
6. 新项目首次绘图时复制技能 `assets/plot_style.toml` 到项目根目录，再按实际组别补充。仅建立项目、写代码或讨论风格，不触发创建。

## 配置是绘图样式的唯一维护入口

- 绘图代码每次运行解析选定 TOML，并把配置值传给绘图库。禁止仅写入一个没有被代码读取的装饰性配置文件。
- 新模板按此顺序解析：`base` → `profiles.<所选用途>` → `figures.<稳定图ID>.style`，逐键覆盖；全局组别映射再叠加当前图的 `groups` override。`palettes` 和 `semantic_colors` 是共享资源。
- 保留现有 schema 时使用现有读取方式；不要求为了匹配本模板而整体迁移项目。若必须适配，局限在绘图层，保持旧图兼容。
- 风格参数写入 TOML；图形内容和统计计算保留在分析代码或结果数据中。TOML 可以记录图的显示范围、标签选择与布局设置，不存放密钥、原始大数据或未经验证的分析结论。
- `figure_legend` 表记录正式图的完整图注策略、放置方式和正文文件路径；正文独立保存为随图 Markdown，默认图下呈现。多张正式图应分别使用对应图 ID 的文件路径，避免相互覆盖；本模板的 `figure_legend.md` 是单张图的起始名称。
- Python 与 R 使用同一份 TOML 语义。用可用的解析器；不要仅为风格任务改换项目语言。
- 按配置字段的物理单位映射到绘图库。`*_pt` 是点，`*_in` 是英寸，`marker_size_pt2` 是点面积；不同库的点大小、线宽单位可能不同，不能把 Matplotlib 的 `s` 原数值直接当作 ggplot2 的 `size`。

## 持久颜色注册表

- `groups` 使用有稳定含义的键，例如条件名称或项目约定 ID，不使用本次排序后的第 1/2/3 组。
- 首次遇到新组别，从项目色板选择颜色并写入 `groups`。已有组别的颜色不随筛选、排序或暂时缺席而改变。
- 如果多个图共享同一比较体系，复用相同键；不同语义体系可用 `condition:control`、`cell_type:T_cell` 等命名空间，避免误把同名类别当作相同对象。
- 不凭名字猜测统计角色；确认组别含义后才将其映射到参考灰、强调色或上下调色。已有项目映射优先。
- 类别超过色板可区分的数量时，采用分面、编号或直接标注；不要无说明循环颜色并声称每一类都具有独立颜色。

## 修改与保存

- 用户要求改配色、字号、图例或风格时，修改生效的 TOML 并重绘；不另写一套只在当前脚本里生效的硬编码。
- “以后都这样”“整个项目”修改共享值；“只改这张”使用 `figures.<图ID>` override。未明确范围时沿当前图作用域处理，并说明；不把一张图的修改悄悄推广到全项目。
- 保留未知字段、其他图的 override、项目注释和已登记的组别。优先使用保留格式的 TOML 编辑器，或对目标位置作最小编辑；解析器不应全量重写并丢弃注释。
- 组别颜色在项目级改变时，更新本次任务涉及的图；说明其他已导出的旧图不会自动刷新，不擅自重跑全部历史分析。
- 写入后重新解析 TOML，确认类型、合法颜色、正的尺寸/字号、`alpha` 范围和选定 profile 的必需项；按修改后的配置生成预览。
- 不在每次普通配置修改前重复索要授权；用户绘图及样式修改请求已覆盖必要的项目配置编辑。处理不清楚且影响输出的选择时才询问。

## 可复现性

最终回复简要报告配置路径、用途 profile 和有意义的变更。正式图在现有项目记录或相邻简短元数据中记录源数据标识、选定配置及图 ID；若有随机抽样或布局，记录随机种子。无需每张探索图生成一套审计文件。

相对路径以项目根目录解析；技能内引用以技能目录解析。不要把开发这份技能时的个人文件路径写入新项目。
